# 정보 구조 (IA)

## 라우트 맵

| ID   | 경로                 | 화면                                                  | 역할 | 라우트 이름        |
| ---- | -------------------- | ----------------------------------------------------- | ---- | ------------------ |
| S-00 | `/`                  | 역할 선택                                             | 공통 | `role-select`      |
| S-10 | `/teacher/rooms`     | 자습실 목록 (관리)                                    | 강사 | `teacher-rooms`    |
| S-11 | `/teacher/rooms/:id` | 자습실 상세 + 이력 타임라인                           | 강사 | `teacher-room`     |
| S-12 | (다이얼로그)         | 자습실 등록·수정 폼                                   | 강사 | -                  |
| S-13 | `/teacher/students`  | 학생 목록 (·관리)                                     | 강사 | `teacher-students` |
| S-20 | `/student/rooms`     | 자습실 목록 (신청)                                    | 학생 | `student-rooms`    |
| S-21 | `/student/visits`    | 내 신청 목록                                          | 학생 | `student-visits`   |
| S-22 | `/student/rooms/:id` | 자습실 페이지 (시간 + 좌석 신청, `?edit=1` 변경 모드) | 학생 | `student-room`     |
| -    | `/:pathMatch(.*)*`   | 404                                                   | 공통 | `not-found`        |

**등록·수정 폼은 페이지가 아니라 다이얼로그로 만듭니다.** 입력 항목이 3~4개뿐이고, 목록 맥락(다른 자습실의 기간·정원)을 보면서 입력하는 편이 낫기 때문입니다. 다만 다이얼로그 열림 상태를 URL 쿼리(`?edit=3`, `?new=1`)에 반영해 새로고침·뒤로가기에도 유지합니다.

## 내비게이션

```
┌──────────────────────────────────────────────────────────┐
│ 자습실 예약   [자습실] [학생]              강사 · 역할 바꾸기 │  ← 강사
│ 자습실 예약   [자습실] [내 신청 2]         김하늘 · 역할 바꾸기 │  ← 학생
└──────────────────────────────────────────────────────────┘
```

- 상단 바 하나로 충분합니다(메뉴 2개). 사이드바는 쓰지 않습니다.
- 학생의 "내 신청" 탭에는 유효 신청 수를 배지로 붙입니다(상태 확인 문제 해결).
- 현재 역할과 이름을 오른쪽에 항상 보여, "누구로 보고 있는지" 헷갈리지 않게 합니다.
- 모바일(< 640px)에서는 같은 상단 바를 유지하되 메뉴를 아이콘+짧은 라벨로 줄입니다.

## 화면 ↔ 기능 ↔ 요구사항 매핑

| 화면 | 기능 (FN)                                         | 요구사항 (FR)                     | API                                                                                     |
| ---- | ------------------------------------------------- | --------------------------------- | --------------------------------------------------------------------------------------- |
| S-00 | 역할·학생 선택                                    | (로그인 대체)                     | `GET /students`                                                                         |
| S-10 | FN-ROM-01 목록, FN-ROM-04 삭제                    | FR-ROM-01, FR-ROM-05              | `GET /study-rooms`, `DELETE /study-rooms/:id`                                           |
| S-11 | FN-ROM-03 상세·이력, FN-ROM-04 삭제               | FR-ROM-03, FR-ROM-05              | `GET /study-rooms/:id`, `GET /study-rooms/:id/histories`, `GET /study-rooms/:id/visits` |
| S-12 | FN-ROM-02 등록·수정, FN-ROM-05 기존 신청 처리     | FR-ROM-02, FR-ROM-04, (FR-ROM-06) | `POST`, `PATCH /study-rooms/:id`                                                        |
| S-13 | FN-STD-01 목록, (FN-STD-02 관리)                  | FR-STD-01, (FR-STD-02)            | `GET /students` (`POST/PATCH/DELETE`)                                                   |
| S-20 | FN-ROM-01 목록, FN-VST-01 신청 진입               | FR-ROM-01, FR-VST-01              | `GET /study-rooms` (내 신청 여부: 방문 API에서 확정)                                    |
| S-21 | FN-VST-02 수정, FN-VST-03 취소, FN-VST-04 내 신청 | FR-VST-02, FR-VST-03, FR-VST-04   | `GET /students/:id/visits`, `PATCH /visits/:id`, `POST /visits/:id/cancel`              |
| S-22 | FN-VST-01 신청, FN-VST-02 수정                    | FR-VST-01, FR-VST-02              | `POST /visits`, `PATCH /visits/:id`                                                     |

괄호는 선택 요구사항입니다. 자습실(`/study-rooms`)·학생(`/students`) API는 구현되어 있고(Swagger `/api/docs`), 방문(`/visits`) 경로는 방문 API 구현 이슈에서 확정되면 갱신합니다.

## 클라이언트 상태

| 상태                             | 위치                                                    | 비고                                                                        |
| -------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------- |
| 현재 역할, 선택한 학생           | Pinia `useSessionStore` + `localStorage`                | 라우터 가드가 참조                                                          |
| 서버 데이터(목록·상세)           | 화면별 composable (`useStudyRooms` 등)                  | 전역 캐시를 두지 않고 화면 진입 시 조회, 변경 후 재조회                     |
| 다이얼로그 열림                  | URL 쿼리                                                | 새로고침·공유에도 유지                                                      |
| 신청 다이얼로그에 미리 고른 시간 | URL 쿼리 `slot=YYYY-MM-DDTHH:mm~HH:mm` (`apply`와 함께) | 정원 마감 후 다른 자습실 안내(S-23)에서 사용, 다이얼로그를 닫으면 함께 지움 |
| 토스트                           | Reka UI `ToastProvider` + composable                    | 전역 1개                                                                    |

서버 데이터를 전역 스토어에 두지 않는 이유: 정원은 다른 학생의 신청으로 계속 바뀌므로, 캐시보다 "변경 직후·화면 진입 시 다시 조회"가 단순하고 정확합니다.
