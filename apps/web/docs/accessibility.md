# 접근성

목표는 **WCAG 2.2 AA**입니다. Reka UI가 다이얼로그·셀렉트·탭의 키보드/ARIA 동작을 제공하므로, 직접 만드는 부분(버튼, 카드, 폼 필드, 상태 표시)을 중점적으로 챙깁니다. 화면을 구현할 때마다 `better-accessibility`로 검토하고, PR 전에 `impeccable audit`을 돌립니다.

## 체크리스트

### 지각

- [x] 텍스트 대비 4.5:1 이상, 큰 텍스트·UI 경계 3:1 이상 (`better-colors`로 측정)
- [x] 상태(정원 마감, 신청됨, 취소됨)를 색만이 아니라 텍스트로도 전달
- [x] CapacityBar는 `role="meter"` 또는 텍스트 `7 / 10명`을 함께 제공
- [x] 200% 확대, 320px 너비에서 가로 스크롤 없이 사용 가능

### 조작

- [x] 모든 기능을 키보드만으로 사용 가능 (카드 클릭 영역은 실제 `<a>`/`<button>`)
- [x] 포커스 링이 항상 보임 (`:focus-visible`, 2px 이상, 대비 3:1)
- [x] 다이얼로그 열면 첫 입력으로 포커스, 닫으면 연 버튼으로 복귀 (Reka UI 기본)
- [x] 터치 대상 최소 24×24px, 주요 버튼 40px 이상 (WCAG 2.2 2.5.8)
- [x] 비활성 버튼의 이유를 키보드 사용자도 알 수 있게 (툴팁 대신 버튼 옆 텍스트 우선)

### 이해

- [x] 모든 입력에 `<label>`, 에러는 `aria-describedby` + `aria-invalid`
- [x] 제출 실패 시 첫 에러 필드로 포커스
- [x] 파괴적 액션은 확인 다이얼로그, 기본 포커스는 안전한 버튼
- [x] 페이지마다 `<h1>` 1개, 문서 `<title>`을 화면별로 갱신 (`자습실 목록 · 자습실 예약`)
- [x] `<html lang="ko">`

### 견고성

- [x] 토스트는 `aria-live="polite"`, 에러 토스트는 `assertive`
- [x] 목록 재조회 후 결과 수 변화를 live region으로 알림 ("자습실 5개")
- [x] 라우트 이동 시 새 페이지 `<h1>`으로 포커스 이동
- [x] `prefers-reduced-motion` 존중
