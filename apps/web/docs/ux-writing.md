# UX 라이팅

## 톤

- 해요체. 짧고 구체적으로. 시스템 관점("요청이 처리되었습니다")이 아니라 사용자 관점("방문을 신청했어요").
- 에러는 **무엇이 문제인지 + 어떻게 하면 되는지**를 한 문장에.
- 느낌표·이모지를 쓰지 않습니다.

## 용어집

화면·코드·문서에서 같은 말을 씁니다.

| 쓰는 말          | 쓰지 않는 말            | 코드                     | 설명                                 |
| ---------------- | ----------------------- | ------------------------ | ------------------------------------ |
| 자습실           | 스터디룸, 방            | `StudyRoom`              |                                      |
| 운영 기간        | 오픈 기간, 기간         | `startDate`~`endDate`    | 자습실이 열려 있는 시작~종료 일시    |
| 최대 인원 / 정원 | 수용 인원               | `maxPersonnel`           | 강사 화면 "최대 인원", 표시는 "정원" |
| 남은 자리        | 잔여석                  | -                        | 학생 화면 전용                       |
| 방문 신청        | 예약, 등록              | `Visit`                  | 동사: 신청하다                       |
| 방문 시간        | 이용 시간               | `startAt`~`endAt`        |                                      |
| 시간 변경        | 수정                    | `UPDATE`                 | 학생 화면 버튼은 "시간 변경"         |
| 취소             | 삭제(방문에 대해)       | `CANCELED`               | 방문은 "취소", 자습실·학생은 "삭제"  |
| 이력             | 로그, 기록              | `VisitHistory`           |                                      |
| 강사 / 학생      | 관리자, 선생님 / 사용자 | `INSTRUCTOR` / `STUDENT` |                                      |

## 버튼 라벨

동사로 끝내고, 결과를 예측할 수 있게 씁니다.

| 위치           | 라벨                      |
| -------------- | ------------------------- |
| 자습실 등록    | 새 자습실 → (폼) 저장     |
| 방문 신청      | 방문 신청 → (폼) 신청하기 |
| 시간 수정      | 시간 변경 → (폼) 변경하기 |
| 방문 취소 확인 | 방문 취소 / 닫기          |
| 삭제 확인      | 삭제 / 닫기               |
| 역할 전환      | 역할 바꾸기               |

확인 다이얼로그의 닫기 버튼은 "취소"라고 쓰지 않습니다(방문 "취소"와 헷갈림).

## 성공 토스트

| 액션        | 문구                                 |
| ----------- | ------------------------------------ |
| 자습실 등록 | 자습실을 열었어요                    |
| 자습실 수정 | 변경 내용을 저장했어요               |
| 자습실 삭제 | 자습실을 삭제했어요                  |
| 방문 신청   | 방문을 신청했어요. 11.20 18:00–20:00 |
| 시간 변경   | 방문 시간을 바꿨어요. 19:00 → 18:00  |
| 방문 취소   | 방문을 취소했어요                    |

## 에러 메시지

| 상황              | 문구                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| 이름 비어 있음    | 자습실 이름을 적어 주세요                                              |
| 최대 인원 < 1     | 최대 인원은 1명 이상이어야 해요                                        |
| 시작 ≥ 종료       | 종료 일시는 시작보다 늦어야 해요                                       |
| 정원 축소 불가    | 현재 {n}명이 신청했어요. {n}명 이상으로 정해 주세요                    |
| 정원 초과 (서버)  | 방금 정원이 다 찼어요. 다른 자습실을 골라 주세요                       |
| 중복 신청         | 이미 신청한 자습실이에요. 시간을 바꾸려면 내 신청에서 변경해 주세요    |
| 운영 기간 밖      | 운영 기간({기간}) 안에서 골라 주세요                                   |
| 삭제된 자습실     | 삭제된 자습실이에요                                                    |
| 기간 밖 신청 존재 | 새 운영 기간 밖에 있는 신청이 있어요. 학생과 시간을 먼저 조율해 주세요 |
| 전화번호 중복     | 이미 등록된 전화번호예요                                               |
| 네트워크·서버     | 연결이 불안정해요. 잠시 후 다시 시도해 주세요                          |

## 날짜·시간 표기

`Intl.DateTimeFormat('ko-KR')`, 브라우저 시간대(Asia/Seoul 가정). 서버와는 오프셋이 붙은 ISO 8601로 주고받습니다. 응답은 항상 KST(`2026-11-15T19:00:00.000+09:00`)로 오고, 요청은 오프셋만 있으면 어느 시간대든 됩니다(`IsoDateString`, `packages/shared/src/study-room.ts`).

| 경우            | 표기                                  |
| --------------- | ------------------------------------- |
| 어제·오늘·내일  | `오늘 20:00 – 22:00`, `내일 09:00`    |
| 날짜+시간       | `11.20(목) 18:00`                     |
| 같은 날 구간    | `11.20(목) 18:00 – 22:00`             |
| 다른 날 구간    | `11.20(목) 18:00 – 11.21(금) 02:00`   |
| 올해가 아닐 때  | `2027.01.05(화) 18:00`                |
| 이력 타임스탬프 | `11.15 14:02`, 1시간 이내면 `12분 전` |

구간 구분자는 en dash(`–`)를 쓰고 앞뒤에 공백을 둡니다.
