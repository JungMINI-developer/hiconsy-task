# 인터랙션 규칙

## 폼 검증

클라이언트 검증은 **안내용**이고, 서버 검증이 최종 기준입니다. 같은 규칙을 양쪽에 두되 메시지는 [ux-writing.md](./ux-writing.md#에러-메시지)를 씁니다.

### 자습실 (S-12)

| 필드             | 규칙                                   | 검증 시점            |
| ---------------- | -------------------------------------- | -------------------- |
| 이름             | 필수, 1~100자, 앞뒤 공백 제거          | blur, 제출           |
| 최대 인원        | 정수, 1 이상 (상한 200 제안)           | 입력 즉시            |
| 운영 시작·종료   | 필수, 시작 < 종료                      | 둘 다 입력된 뒤 즉시 |
| (수정) 최대 인원 | 현재 신청 인원 이상이어야 함 (아래 #7) | 입력 즉시, 경고      |
| (수정) 운영 기간 | 기존 신청이 밖으로 밀리면 경고 (#8)    | 입력 즉시, 경고      |

### 방문 (S-22)

| 규칙                      | UI 처리                                           |
| ------------------------- | ------------------------------------------------- |
| 구간 전체가 운영 기간 안  | 선택지에서 운영 기간 밖을 제외 (입력 자체를 막음) |
| 시작 < 종료               | 종료 선택지를 시작 이후로 제한                    |
| 과거 시간 불가 (#6)       | 현재 시각 이전 선택지 제외                        |
| 정원 남아 있음            | 남은 자리 0이면 신청 버튼 비활성 + 이유           |
| 유효 신청 1건 (중복 금지) | 이미 신청한 자습실은 [신청] 대신 [시간 변경]      |

### 공통

- 에러는 필드 바로 아래에 표시하고 `aria-describedby`로 연결합니다.
- 제출 시 첫 번째 에러 필드로 포커스를 옮깁니다.
- 처음 입력 중일 때는 에러를 띄우지 않고(blur 이후부터), 한 번 에러가 나면 고칠 때마다 즉시 다시 검사합니다.

## 서버 응답 처리

`packages/shared`의 `ApiError { code, message, details? }`를 axios 인터셉터에서 정규화한 뒤, 코드별로 처리합니다.

| 상황           | 예상 응답                   | UI 처리                                                                 |
| -------------- | --------------------------- | ----------------------------------------------------------------------- |
| 입력 검증 실패 | 400 `BAD_REQUEST` + details | 폼 상단에 요약, 가능하면 필드에 매핑. 다이얼로그 유지                   |
| 정원 초과      | 409 (코드 BE 확정 시 갱신)  | "방금 정원이 다 찼어요" 토스트 + 목록 재조회 + 다이얼로그 닫기          |
| 이미 신청함    | 409                         | "이미 신청한 자습실이에요" + 내 신청으로 이동 버튼                      |
| 운영 기간 밖   | 400/422                     | 필드 에러로 표시 (클라이언트 검증을 통과했다면 기간이 바뀐 것 → 재조회) |
| 삭제된 자습실  | 404                         | "삭제된 자습실이에요" + 목록 재조회                                     |
| 네트워크·5xx   | -                           | "잠시 후 다시 시도해 주세요" + [다시 시도]. 입력값은 유지               |

> 정원·중복 에러를 구분할 수 있도록 BE에 **도메인 에러 코드**(예: `ROOM_FULL`, `DUPLICATE_VISIT`, `OUT_OF_PERIOD`, `ROOM_DELETED`)를 요청합니다. 현재 `code`는 HTTP 상태 기반이라 409 두 종류를 구분하지 못합니다.

## 확인 다이얼로그

되돌릴 수 없는 액션에만 띄웁니다(Reka UI `AlertDialog`). 기본 포커스는 **안전한 쪽(닫기)** 버튼에 둡니다.

| 액션             | 제목                 | 본문                                                                                 | 확인 버튼 |
| ---------------- | -------------------- | ------------------------------------------------------------------------------------ | --------- |
| 방문 취소        | 방문을 취소할까요?   | 3층 A 자습실 · 11.20 18:00–20:00. 취소해도 자리가 남아 있으면 다시 신청할 수 있어요. | 방문 취소 |
| 자습실 삭제      | 자습실을 삭제할까요? | 신청한 학생 7명의 신청이 모두 취소돼요.                                              | 삭제      |
| 학생 삭제 (선택) | 학생을 삭제할까요?   | 유효 신청 2건이 취소돼요.                                                            | 삭제      |

## 낙관적 업데이트를 하지 않는 이유

정원은 다른 학생과 경쟁하는 자원입니다. 신청·수정은 **서버 응답 후** 화면을 갱신하고, 응답 대기 중에는 버튼에 로딩을 보여줍니다. 대신 응답이 300ms 안에 오도록 BE를 단순하게 유지합니다.

## 데이터 최신화

- 화면 진입 시, 변경 성공 후, 창이 다시 포커스될 때(`visibilitychange`) 목록을 재조회합니다.
- 409(정원·중복)를 받으면 항상 재조회합니다.
- 폴링·웹소켓은 MVP 범위 밖입니다.

## 미정 규칙에 대한 UI 제안 (requirements 9절)

BE 규칙과 함께 확정되면 requirements.md로 옮깁니다.

| #   | 항목                | UI 제안                                                                                                                               |
| --- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 6   | 과거 시간 신청      | 막는다. 현재 시각 이전 선택지를 제외                                                                                                  |
| 7   | 최대 인원 축소      | **현재 신청 인원 미만으로는 막는다.** 입력 시 "현재 7명이 신청했어요. 7명 이상으로 정해 주세요" (자동 취소는 누구를 뺄지 기준이 모호) |
| 8   | 운영 기간 변경      | 밀려나는 신청이 있으면 경고 다이얼로그에 목록을 보여주고, 확인 시 자동 취소(`actorType=SYSTEM`, `reason` 기록)                        |
| 9   | 자습실 삭제         | 확인 다이얼로그에 영향 인원 표시 → 유효 신청 일괄 취소, 이력 사유 "자습실 삭제"                                                       |
| 10  | 학생 삭제           | 확인 시 유효 신청 취소. 전화번호 중복은 등록 폼에서 경고만(차단 X)                                                                    |
| 11  | 신청 주체 식별      | S-00에서 고른 학생 id. 요청 바디/쿼리에 `studentId` 포함                                                                              |
| 12  | 수정·취소 가능 시점 | 방문 시작 이후에는 수정·취소 버튼을 숨기고 "지난 방문"으로 이동                                                                       |

학생 입장에서 시스템이 내 신청을 취소한 경우(#8, #9) 내 신청 목록의 취소됨 탭에 **사유**를 함께 보여줍니다.
