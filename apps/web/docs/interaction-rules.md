# 인터랙션 규칙

## 폼 검증

클라이언트 검증은 **안내용**이고, 서버 검증이 최종 기준입니다. 같은 규칙을 양쪽에 두되 메시지는 [ux-writing.md](./ux-writing.md#에러-메시지)를 씁니다.

### 자습실 (S-12)

| 필드             | 규칙                                           | 검증 시점            |
| ---------------- | ---------------------------------------------- | -------------------- |
| 이름             | 필수, 1~100자, 앞뒤 공백 제거                  | blur, 제출           |
| 최대 인원        | 정수, 1 이상 (상한 200 제안)                   | 입력 즉시            |
| 운영 시작·종료   | 필수, 시작 < 종료                              | 둘 다 입력된 뒤 즉시 |
| (수정) 최대 인원 | 현재 신청 인원 이상이어야 함 (#7)              | 입력 즉시, 저장 차단 |
| (수정) 운영 기간 | 유효 신청이 새 기간 밖으로 벗어나면 안 됨 (#8) | 서버 409로 확인      |

### 방문 (S-22 자습실 페이지·변경 모드)

| 규칙                           | UI 처리                                                                                                                                                  |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 구간 전체가 운영 기간 안       | 선택지에서 운영 기간 밖을 제외 (입력 자체를 막음)                                                                                                        |
| 시작 < 종료                    | 종료 선택지를 시작 이후로 제한                                                                                                                           |
| 과거 시간 불가 (#6)            | 현재 시각 이전 선택지 제외                                                                                                                               |
| 좌석 (#49)                     | 고른 구간 내내 비어 있는 좌석만 고를 수 있음. 열 때 좌석 하나를 미리 골라 둠. 시간을 바꿔 고른 좌석이 차면 선택을 풀고 토스트. 빈 좌석 0석이면 S-23 안내 |
| 남은 시간에 빈 좌석 없음       | 자습실 카드(S-20)의 [방문 신청] 비활성 + 이유. 지금 다 차 있는 것만으로는 막지 않음                                                                      |
| 유효 신청 1건 (중복 금지)      | 이미 신청한 자습실은 [신청] 대신 [시간 변경]                                                                                                             |
| 내 다른 신청과 겹침 금지 (#13) | 겹치는 시각은 선택지에 남기되 비활성 + "다른 신청" 표시. 기본값은 겹치지 않는 첫 시각. 모든 시간이 겹치면 안내 + 내 신청 링크                            |

### 공통

- 에러는 필드 바로 아래에 표시하고 `aria-describedby`로 연결합니다.
- 제출 시 첫 번째 에러 필드로 포커스를 옮깁니다.
- 처음 입력 중일 때는 에러를 띄우지 않고(blur 이후부터), 한 번 에러가 나면 고칠 때마다 즉시 다시 검사합니다.

## 서버 응답 처리

`packages/shared`의 `ApiError { code, message, details? }`를 axios 인터셉터에서 정규화한 뒤, 코드별로 처리합니다.

도메인 에러 코드는 `packages/shared/src/error-code.ts`의 `ErrorCode`를 그대로 import해 분기합니다. 도메인 코드가 없는 에러는 HTTP 상태명(`BAD_REQUEST`, `NOT_FOUND` 등)이 `code`로 옵니다.

| 상황                    | 응답 (`error.code`)              | UI 처리                                                                                                 |
| ----------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 입력 검증 실패          | 400 `BAD_REQUEST` + `details`    | 폼 상단에 요약, 가능하면 필드에 매핑. 다이얼로그 유지                                                   |
| 시작 ≥ 종료             | `INVALID_PERIOD`                 | 운영 종료 필드 에러                                                                                     |
| 정원 축소 불가 (#7)     | 409 `CAPACITY_BELOW_CURRENT`     | 최대 인원 필드 에러 + 현재 인원 재조회                                                                  |
| 기간 밖 신청 존재 (#8)  | 409 `PERIOD_EXCLUDES_VISITS`     | 다이얼로그 상단에 안내 + [신청자 보기]로 상세 신청자 탭 이동. 다이얼로그 유지                           |
| 없는·삭제된 자습실      | 404 `STUDY_ROOM_NOT_FOUND`       | "삭제된 자습실이에요" + 목록 재조회                                                                     |
| 없는·삭제된 학생        | 404 `STUDENT_NOT_FOUND`          | 학생 화면이면 세션을 비우고 `/`로 이동 (선택한 학생이 삭제된 경우)                                      |
| 전화번호 중복 (#10)     | 409 `DUPLICATE_PHONE`            | 전화번호 필드 에러                                                                                      |
| 좌석 선점됨 (방문, #49) | 409 `SEAT_TAKEN`                 | 다이얼로그 유지 + 좌석 다시 조회 + 선택 해제 + "방금 다른 학생이 {n}번 좌석을 예약했어요" 토스트        |
| 없는 좌석 (방문)        | 404 `SEAT_NOT_FOUND`             | 좌석 다시 조회 + 선택 해제 + 토스트 (그 사이 강사가 좌석을 줄인 경우)                                   |
| 빈 좌석 없음 (방문)     | 409 `CAPACITY_FULL`              | 좌석을 항상 보내므로 보통 나오지 않음. 나오면 좌석 다시 조회 + 토스트                                   |
| 이미 신청함 (방문)      | 409 (방문 API 구현 시 코드 확정) | "이미 신청한 자습실이에요" + 내 신청으로 이동 버튼                                                      |
| 시간 겹침 (방문, #13)   | 409 `VISIT_TIME_OVERLAP`         | 다이얼로그 상단에 안내 + 내 신청 링크, 내 신청 재조회 → 겹치는 신청 표시 + 제출 비활성. 다이얼로그 유지 |
| 운영 기간 밖 (방문)     | (방문 API 구현 시 코드 확정)     | 필드 에러로 표시 (클라이언트 검증을 통과했다면 기간이 바뀐 것 → 재조회)                                 |
| 네트워크·5xx            | -                                | "잠시 후 다시 시도해 주세요" + [다시 시도]. 입력값은 유지                                               |

> 방문 API의 정원 초과·중복 신청·기간 밖 에러도 409를 함께 쓰므로, 같은 방식으로 `ErrorCode`에 도메인 코드를 추가해 구분하도록 방문 API 이슈에 반영합니다.

## 확인 다이얼로그

되돌릴 수 없는 액션에만 띄웁니다(Reka UI `AlertDialog`). 기본 포커스는 **안전한 쪽(닫기)** 버튼에 둡니다.

| 액션             | 제목                 | 본문                                                                                 | 확인 버튼 |
| ---------------- | -------------------- | ------------------------------------------------------------------------------------ | --------- |
| 방문 취소        | 방문을 취소할까요?   | 3층 A 자습실 · 11.20 18:00–20:00. 취소해도 자리가 남아 있으면 다시 신청할 수 있어요. | 방문 취소 |
| 자습실 삭제      | 자습실을 삭제할까요? | 신청한 학생 7명의 신청이 모두 취소돼요.                                              | 삭제      |
| 학생 삭제 (선택) | 학생을 삭제할까요?   | 유효 신청 2건이 취소돼요.                                                            | 삭제      |

## 낙관적 업데이트를 하지 않는 이유

정원은 다른 학생과 경쟁하는 자원입니다. 신청·수정은 **서버 응답 후** 화면을 갱신하고, 응답 대기 중에는 버튼에 로딩을 보여줍니다. 대신 응답이 300ms 안에 오도록 BE를 단순하게 유지합니다.

## 데이터 최신화

- 화면 진입 시, 변경 성공 후, 창이 다시 포커스될 때(`visibilitychange`) 목록을 재조회합니다.
- 409(정원·중복)를 받으면 항상 재조회합니다.
- 폴링·웹소켓은 MVP 범위 밖입니다.

## 9절 규칙의 UI 반영

requirements 9절에서 확정된 규칙(#7~10)은 그대로 따르고, 아직 정하지 않은 항목(#6, #11, #12)은 UI 제안입니다.

| #   | 항목                | 상태 | UI 처리                                                                                                     |
| --- | ------------------- | ---- | ----------------------------------------------------------------------------------------------------------- |
| 6   | 과거 시간 신청      | 제안 | 막는다. 현재 시각 이전 선택지를 제외                                                                        |
| 7   | 최대 인원 축소      | 확정 | 현재 신청 인원 미만이면 **막는다.** 입력 즉시 "현재 7명이 신청했어요. 7명 이상으로 정해 주세요"             |
| 8   | 운영 기간 변경      | 확정 | 유효 신청이 새 기간 밖으로 벗어나면 **막는다.** 서버 409를 받으면 안내하고 강사가 학생과 먼저 조율하게 한다 |
| 9   | 자습실 삭제         | 확정 | 확인 다이얼로그에 영향 인원 표시 → 유효 신청 자동 취소(`SYSTEM`, 사유 "자습실 삭제")                        |
| 10  | 학생 삭제·전화번호  | 확정 | 확인 시 유효 신청 자동 취소(`SYSTEM`, 사유 "학생 삭제"). 전화번호 중복은 **막는다**(`DUPLICATE_PHONE`)      |
| 11  | 신청 주체 식별      | 제안 | S-00에서 고른 학생 id. 요청 바디/쿼리에 `studentId` 포함                                                    |
| 12  | 수정·취소 가능 시점 | 제안 | 방문 시작 이후에는 수정·취소 버튼을 숨기고 "지난 방문"으로 이동                                             |

학생 입장에서 시스템이 내 신청을 취소한 경우(#9) 내 신청 목록의 취소됨 탭에 **사유**를 함께 보여줍니다(`StudyRoomHistory.reason`).
