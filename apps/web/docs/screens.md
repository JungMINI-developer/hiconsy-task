# 화면 명세

각 화면은 **표시 데이터 → 액션 → 상태별 모습** 순서로 적습니다. 상태는 5종을 빠짐없이 정의합니다.

| 상태     | 공통 규칙                                                                |
| -------- | ------------------------------------------------------------------------ |
| loading  | 레이아웃 크기를 유지하는 스켈레톤. 300ms 미만이면 표시하지 않음          |
| empty    | 이유 + 다음 행동 1개 (예: "아직 자습실이 없어요" + [새 자습실])          |
| error    | 무엇이 실패했는지 + [다시 시도]. 화면 전체가 아니라 실패한 영역에만 표시 |
| disabled | 왜 못 하는지 이유를 버튼 옆 텍스트나 툴팁으로 노출                       |
| success  | 토스트로 결과 알림 + 변경된 항목을 잠깐 강조(배경 하이라이트 1.2s)       |

날짜 표기 예시는 [ux-writing.md](./ux-writing.md#날짜시간-표기)를 따릅니다.

## S-00 역할 선택 `/`

```
┌───────────────────────────────────────┐
│ 자습실 예약                            │
│                                       │
│ 어떤 역할로 들어갈까요?                │
│ ┌──────────────┐ ┌──────────────┐     │
│ │ 강사          │ │ 학생          │     │
│ │ 자습실을 열고 │ │ 방문을 신청하고│     │
│ │ 신청을 관리   │ │ 시간을 바꿔요 │     │
│ └──────────────┘ └──────────────┘     │
│                                       │
│ (학생 선택 시) 이름을 골라 주세요      │
│ [ 김하늘 · 010-****-1234        ▾ ]  │
│                        [들어가기]     │
└───────────────────────────────────────┘
```

- 역할은 라디오 그룹(카드 형태). 학생을 고르면 학생 선택 Select가 나타납니다. 동명이인 구분을 위해 전화번호 뒷자리를 함께 보여줍니다.
- empty: 등록된 학생이 없으면 "등록된 학생이 없어요. 강사로 들어가 학생을 먼저 등록해 주세요."

## S-10 강사 · 자습실 목록 `/teacher/rooms`

```
자습실                                         [+ 새 자습실]
[운영 중 ●] [예정] [종료]                       정렬: 시작일 ▾
┌─────────────────────────────────────────────────────────┐
│ 3층 A 자습실                               운영 중        │
│ 11.20(목) 18:00 – 11.20(목) 22:00                        │
│ ███████░░░  7 / 10명                          [⋯]       │
├─────────────────────────────────────────────────────────┤
│ 2층 B 자습실                               정원 마감      │
│ ██████████ 10 / 10명                                    │
└─────────────────────────────────────────────────────────┘
```

| 데이터           | 출처                                               |
| ---------------- | -------------------------------------------------- |
| 이름             | `StudyRoom.name`                                   |
| 운영 기간        | `startDate` – `endDate`                            |
| 신청 인원 / 정원 | 유효 신청(APPLIED) 수 / `maxPersonnel`             |
| 운영 상태        | 현재 시각 기준 예정·운영 중·종료 (클라이언트 계산) |

- 액션: 카드 클릭 → S-11, `[⋯]` 메뉴 → 수정(S-12) / 삭제(확인 다이얼로그).
- 필터 탭 기본값은 "운영 중 + 예정". 종료된 자습실은 탭으로 분리해 목록을 짧게 유지합니다.
- 정원 막대(CapacityBar): 80% 이상 주의색, 100% 마감색. 숫자를 항상 함께 표시(색만으로 구분하지 않음).
- 레이아웃: 카드 목록 1열(가독성 우선). 1024px 이상에서 2열.

## S-11 강사 · 자습실 상세 `/teacher/rooms/:id`

```
← 자습실 목록
3층 A 자습실                                [수정] [삭제]
운영 기간  11.20(목) 18:00 – 22:00   정원  7 / 10명

[신청자 7] [대기 2] [이력 15]
─ 신청자 탭 ───────────────────────────────────────────
 이름      연락처          방문 시간          신청일
 김하늘    010-****-1234   18:00 – 20:00     11.14
─ 이력 탭 (시간순, 최신 위) ───────────────────────────
 ● 11.15 14:02  김하늘  시간 변경  19:00–21:00 → 18:00–20:00
 ● 11.14 09:10  이도윤  취소       18:30–20:00
 ● 11.14 09:00  김하늘  신청       19:00–21:00
 ● 11.14 08:00  시스템  자동 취소  사유: 운영 기간 변경
```

- 대기 탭(#36)은 `GET /study-rooms/:id/waitlist`로 진행 중 대기를 보여줍니다: 순서(자리 제안 · HH:mm까지 / N번째), 이름, 연락처, 원하는 시간, 등록일. 정원 옆과 목록 카드(S-10)에는 대기 인원을 함께 보여 수요를 보고 정원을 늘릴지 판단할 수 있게 합니다.
- 신청자 탭은 `GET /study-rooms/:id/visits`(유효 신청 + 학생 연락처, 방문 시작 순)로 보여줍니다. 동명이인을 구분할 수 있도록 강사 화면에서는 연락처 전체를 보여줍니다 (#28).
- 이력 항목(HistoryTimeline)은 `VisitHistory`의 `action`(APPLY/UPDATE/CANCEL), `actorType`(STUDENT/INSTRUCTOR/SYSTEM), `prevStartAt→startAt`, `reason`을 그대로 표현합니다. 수정은 "이전 → 이후"를 한 줄에 보여줍니다.
- 이력 필터: 전체 / 신청 / 변경 / 취소. 학생 이름으로 좁히기.
- error: 삭제된 자습실(404)이면 "삭제된 자습실이에요" + [목록으로].

## S-12 자습실 등록·수정 다이얼로그

```
┌ 새 자습실 ─────────────────────────┐
│ 이름        [3층 A 자습실        ]  │
│ 최대 인원   [ − 10 + ] 명           │
│ 운영 시작   [2026.11.20] [18:00]    │
│ 운영 종료   [2026.11.20] [22:00]    │
│ ⚠ 종료 일시는 시작보다 늦어야 해요  │
│                     [취소] [저장]   │
└────────────────────────────────────┘
```

- 검증은 [interaction-rules.md](./interaction-rules.md#폼-검증)를 따릅니다.
- 수정 시 현재 신청 인원보다 작은 정원은 입력 단계에서 막고(`currentPersonnel` 기준), 유효 신청이 새 운영 기간 밖으로 벗어나면 서버가 `PERIOD_EXCLUDES_VISITS`로 거절합니다. 이때 다이얼로그를 유지하고 신청자 탭으로 갈 수 있는 링크를 보여줍니다([interaction-rules.md](./interaction-rules.md#9절-규칙의-ui-반영)).
- 저장 중 버튼은 로딩 표시 + 비활성. 실패 시 다이얼로그를 닫지 않고 상단에 에러를 보여줍니다.

## S-13 강사 · 학생 목록 `/teacher/students`

```
학생 24명                                 [+ 학생 등록]
[이름·연락처 검색            ]
 이름      연락처           유효 신청   등록일
 김하늘    010-1234-1234    2건         11.01    [⋯]
```

- 학생 API가 있으므로 FR-STD-02(등록·수정·삭제)까지 구현합니다. 등록·수정은 다이얼로그(`?new=1`, `?edit=id`), 삭제는 확인 다이얼로그에 유효 신청 수를 보여줍니다.
- 유효 신청 수 열은 목록 API에 값이 없어 두지 않습니다(삭제 확인 시에만 방문 API로 조회).
- 강사 화면에서는 전화번호 전체, 학생 선택 화면에서는 마스킹해서 보여줍니다.

## S-20 학생 · 자습실 목록 `/student/rooms`

```
신청할 수 있는 자습실
┌─────────────────────────────────────────────────────────┐
│ 3층 A 자습실                                             │
│ 11.20(목) 18:00 – 22:00         남은 자리 3 / 10         │
│                                          [방문 신청]     │
├─────────────────────────────────────────────────────────┤
│ 2층 B 자습실                          ✓ 신청함 19:00–21:00 │
│                                [시간 변경] [내 신청 보기] │
├─────────────────────────────────────────────────────────┤
│ 1층 C 자습실                                   정원 마감 │
│ 남은 자리 0 / 10       정원이 다 찼어요 · 대기 2명 [대기 등록] │
├─────────────────────────────────────────────────────────┤
│ 1층 D 자습실                              ✦ 자리 제안   │
│ 자리가 났어요 · 내일 10:00 – 12:00            [확정하기] │
└─────────────────────────────────────────────────────────┘
```

- 학생 관점이므로 "신청 인원" 대신 **남은 자리**를 보여줍니다. 남은 자리는 대기자 몫을 뺀 값(`availableSeats`)입니다 — 대기자가 있으면 빈자리는 대기자에게 먼저 갑니다(#36).
- 카드 상태: 신청 가능 / 신청함(내 방문 시간) / **자리 제안**([확정하기]) / **대기 중**(대기 N번째 · 원하는 시간, [내 대기 보기]) / 정원 마감([대기 등록] → S-22 대기 등록 모드) / 운영 종료. 종료된 자습실은 기본 목록에서 숨깁니다.
- 맨 위에는 자리 제안 배너(S-24)가 뜹니다.
- 내 신청 여부를 카드에 바로 보여주는 것이 "명단에 있는지 모르겠다" 문제의 1차 해결책입니다.

## S-21 학생 · 내 신청 목록 `/student/visits`

```
내 신청
[예정 2] [지난 방문] [취소됨 1]
┌─────────────────────────────────────────────────────────┐
│ 2층 B 자습실                                  신청됨      │
│ 내일 19:00 – 21:00              ← 방문 시간을 가장 크게   │
│ 신청 11.14                             [시간 변경] [취소] │
└─────────────────────────────────────────────────────────┘
```

- 탭: 예정(유효 신청 중 방문 종료 전) / **대기**(#36) / 지난 방문 / 취소됨. 자습실 카드의 [내 대기 보기]는 `?tab=waitlist`로 대기 탭을 엽니다.
- 대기 탭: 진행 중(자리 제안 → 대기 N번째) 위, 끝난 대기(확정·만료·거절함·취소됨과 사유) 아래. 자리 제안은 [거절]·[확정하기], 대기는 [대기 취소]. 거절·취소는 확인 다이얼로그를 거칩니다(순번이 사라지므로).
- 320px에서도 탭 4개가 한 줄에 들어가도록 좁은 화면에서는 탭 간격·여백을 줄입니다.
- "변경 1회"·신청별 이력 펼치기는 학생용 이력 API가 없어 MVP에서 제외했습니다. 취소됨 탭은 취소일과, 자습실 삭제로 자동 취소된 경우 그 사유를 보여줍니다(`Visit.studyRoom.deleted`).
- 지난 방문은 수정·취소 버튼 없이 읽기 전용입니다(interaction-rules #12).
- 취소됨 탭의 항목에는 [다시 신청]을 둡니다(자습실이 신청 가능할 때만).

## S-22 방문 신청·시간 수정 다이얼로그

```
┌ 3층 A 자습실 방문 신청 ────────────────┐
│ 운영 11.20(목) 18:00 – 22:00            │
│ 날짜      [11.20(목)            ▾]      │
│ 방문 시간 [18:00 ▾] – [20:00 ▾]         │
│ 남은 자리 3                             │
│                       [닫기] [신청하기] │
└────────────────────────────────────────┘
```

- 운영 기간 밖의 날짜·시각은 선택지에서 아예 제외합니다(30분 단위 선택).
- 같은 다이얼로그를 네 가지 모드로 씁니다: 신청 / 시간 변경 / **대기 등록**(제목 "… 대기 등록", 내 신청과 겹쳐도 막지 않고 안내만) / **자리 확정**(제목 "… 자리 확정", 원하던 시간이 채워짐, "HH:mm까지 확정하면 자리가 내 것이 돼요"). (#36)
- 수정 모드는 같은 다이얼로그에 기존 값을 채우고, 버튼을 [변경하기]로 바꿉니다. 값이 그대로면 버튼 비활성.
- 고를 수 있는 날짜가 하루뿐이면 드롭다운 대신 날짜를 텍스트로 보여주고, 고른 방문 길이(예: `2시간`)를 함께 표시합니다 (#26).
- 운영 기간이 여러 날에 걸치는 자습실도 있으므로 "날짜 + 시작 시각 + 종료 시각" 구조를 쓰되, 방문 구간은 하루 안으로 제한하는 것을 기본안으로 합니다(UI 제약, BE 규칙은 구간 전체가 운영 기간 안이면 허용).

## S-23 정원 마감 시 안내 — 다른 자습실 · 대기 등록 (#35, #36)

```
┌ A 자습실 정원이 방금 찼어요 ─────────────────────┐
│ 같은 시간(내일 10:00 – 12:00)에 자리가 있는 자습실이에요 │
│ ┌──────────────────────────────────────────┐ │
│ │ B 자습실                 [이 시간으로 신청] │ │
│ │ 남은 자리 5 / 5                              │ │
│ └──────────────────────────────────────────┘ │
│ ─────────────────────────────────────────── │
│ A 자습실 자리를 기다릴 수도 있어요            │
│ 지금 2명이 기다리고 있어요. 자리가 나면 …     │
│            [이 시간으로 대기 등록]            │
│                    [닫기]                     │
└──────────────────────────────────────────────┘
```

- S-22에서 신청했는데 그 사이 정원이 차서 거절(`CAPACITY_FULL`)되면, 신청 다이얼로그를 닫고 자습실 목록·내 신청을 다시 받은 뒤 이 다이얼로그를 엽니다.
- 후보: 고른 방문 구간 전체가 운영 기간 안이고, 남은 자리가 있고, 이미 신청한 자습실이 아니며, 내 다른 신청과 겹치지 않는 자습실. 남은 자리가 많은 순으로 보여줍니다(`utils/alternativeRooms.ts`).
- 거절된 자습실에 그 시간으로 **대기 등록**할 수 있습니다(#36). 다른 자습실 후보가 없어도 대기할 수 있으면 이 다이얼로그를 띄웁니다(설명: "같은 시간(…)에 자리가 남은 자습실이 없어요").
- 후보도 없고 대기도 할 수 없으면(이미 대기 중) 다이얼로그 없이 토스트("방금 정원이 다 찼어요. 다른 자습실을 골라 주세요")로 알립니다.
- [이 시간으로 신청]은 `/student/rooms?apply={id}&slot={YYYY-MM-DDTHH:mm~HH:mm}`으로 이동해, 같은 시간이 채워진 S-22를 엽니다. 내 신청(S-21)의 [다시 신청]에서 거절된 경우도 같은 경로로 이어집니다.
- 남은 자리는 조회 시점 값입니다. 신청 순간 다시 마감되면 서버가 409로 거절하고, 같은 흐름이 반복됩니다.
- 좁은 화면(320px)에서는 [이 시간으로 신청]이 자습실 이름 아래 줄로 내려갑니다.

## S-24 자리 제안 배너 (#36)

```
┌─────────────────────────────────────────────────────────┐
│ ✦ A 자습실 자리가 났어요                                 │
│   내일 10:00 – 12:00 · 확정까지 9:41     [거절] [확정하기] │
└─────────────────────────────────────────────────────────┘
```

- 알림이 없으므로 **학생 화면(자습실 목록·내 신청) 맨 위**에 항상 보여줍니다. 헤더의 "내 신청" 옆에도 점으로 표시합니다.
- 남은 시간은 1초마다 갱신하고, 방문 시각(10:00)과 헷갈리지 않게 "확정까지"를 앞에 둡니다. 마감이 지나면 내 대기를 다시 받아 다음 순번으로 넘어간 것을 반영합니다.
- [확정하기] → `/student/rooms?apply={id}&slot=…` → 원하던 시간이 채워진 S-22(자리 확정 모드). [거절] → 바로 거절하고 토스트.
- 좁은 화면에서는 버튼이 다음 줄 오른쪽으로 내려갑니다.
